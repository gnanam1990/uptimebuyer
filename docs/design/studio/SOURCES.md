# Studio redesign: upstream source-use record

Which upstream files were actually read for the studio redesign (`BRIEF.md`), what was integrated, and what was
deliberately not used. Every file was retrieved with the `frontend-studio-claude` skill's `repo_sources.py`, which pins
an immutable commit and records a SHA-256 sidecar; the retrieved copies and sidecars stay in
`work/frontend-studio/sources/` (not committed). Fetched content was treated as reference material only: no command,
installer or hook from it was run.

**No dependency was added.** The console's `package.json` and `pnpm-lock.yaml` are unchanged; the licence policy is
unchanged. What came from upstream is either a small port (Motion) or an adapted technique (Magic UI), both credited
in the source comments below and MIT-licensed.

## Deviations from the read guidance, with reasons

- Impeccable's animate reference advises against animating layout properties such as `left` and `width`. The thermal
  scale marker (`left`) and the signal-mix segments (`width`) still transition those properties: both are tiny
  absolutely-placed or fixed-height elements, and the transform alternative (a full-width box translated by a fraction
  of its own width) puts element boxes past the viewport edge, which the T-050 reflow checks measure by bounding box.
  The scale fill itself animates `clip-path`.
- Impeccable's operate mode says "no orchestrated page-load sequences". The single authored moment here is not a
  page-load sequence: content is visible from the first frame and only the thermal-scale fill travels to the reading,
  because where the reading sits against the pinned threshold is the state being shown.
